## 04장 가상 클라우드 서버 파악하기

### 4.1 가상 클라우드 서버, 아마존 EC2란?

AWS에서 제공하는 유연하고 크기 조절이 가능한 클라우드 컴퓨팅 서버로, 실제 백엔드 애플리케이션 코드가 배포되고 실행되는 환경임.

### 4.2 가상 클라우드 서버, 아마존 EC2 살펴보기

#### 4.2.1 AMI (Amazon Machine Image)

서버 실행에 필요한 운영체제(예: Amazon Linux 2023)와 소프트웨어 설정이 포함된 템플릿임.

#### 4.2.2 인스턴스 유형

서버의 하드웨어 스펙을 의미하며, 컴퓨팅/메모리/스토리지 최적화 등 목적에 따라 다양하게 선택할 수 있음 (예: 프리티어용 `t2.micro`).

#### 4.2.3 스토리지 옵션

인스턴스 종료 시 데이터가 날아가는 휘발성 '인스턴스 스토어 볼륨'과 독립적으로 유지 및 관리되는 비휘발성 'EBS 볼륨'이 있음.

#### 4.2.4 보안 그룹

네트워크 트래픽을 IP 주소와 포트, 프로토콜 기반으로 허용/차단하는 인스턴스 레벨의 가상 방화벽임.

#### 4.2.5 키 페어

EC2 인스턴스에 안전하게 원격 접속하기 위한 열쇠임. 클라우드포메이션으로 생성 시 AWS Systems Manager의 파라미터 스토어에 암호화되어 저장되므로, 이를 복호화하여 로컬에 `.pem` 파일로 만들어 사용함.

### 4.3 아마존 EC2 구축하기

#### 4.3.1 맥OS 환경에서 EC2 인스턴스 접속

- 보안을 위해 다운로드한 `.pem` 키 페어 파일의 권한을 `chmod 400` 명령어로 축소해야만 접속이 허용됨.
- 터미널에서 `ssh -i <키페어.pem> ec2-user@<IP>` 명령어로 접속함.

#### 4.3.2 윈도우 환경에서 EC2 인스턴스 접속

- 테라텀(Tera Term) 클라이언트를 활용함.
- 퍼블릭 IP를 입력하고, 보안 경고창에서 known-host에 추가한 뒤, 사용자 이름(`ec2-user`)과 `.pem` 키를 업로드하여 로그인함.

### 4.4 아마존 EC2 접속 패턴 살펴보기

인스턴스 배치(퍼블릭/프라이빗) 및 보안 요구사항에 따라 4가지 주요 접속 패턴이 있음.

#### 4.4.1 인터넷을 통한 EC2 인스턴스 접속

퍼블릭 서브넷에 인스턴스를 배치하고 인터넷 게이트웨이를 통해 직접 연결하는 가장 직관적인 방식임. 단, 인스턴스가 외부에 노출되므로 실무 운영 환경에서는 권장되지 않음.

#### 4.4.2 EC2 인스턴스 연결 엔드포인트 이용

EIC(EC2 Instance Connect Endpoint)를 활용하면 인터넷 게이트웨이나 퍼블릭 IP 없이도 프라이빗 서브넷의 인스턴스에 안전하게 접속할 수 있음.

- 접속 터널 유지 시간은 최대 1시간임.

#### 4.4.3 세션 관리자 이용한 콘솔에서의 접속

AWS Systems Manager의 세션 관리자를 이용하면 별도의 인바운드 보안 그룹 규칙(예: SSH 22번 포트)을 열람할 필요 없이 브라우저에서 안전하게 접근 가능함.

- 단, 인스턴스에 `AmazonSSMManagedInstanceCore` 정책이 포함된 IAM 인스턴스 프로파일 역할이 반드시 부여되어 있어야 함.

#### 4.4.4 세션 관리자 이용한 포트 포워딩 접속

콘솔에 로그인하지 않고 로컬 환경에서 AWS CLI를 사용해 안전한 포트 포워딩 터널을 뚫는 방식임.

- `aws ssm start-session` 명령어로 로컬 포트(예: 8080)와 대상 인스턴스 포트를 연결한 후, 로컬호스트(`localhost`)를 타겟으로 SSH 터미널이나 테라텀을 통해 우회 접속함.
